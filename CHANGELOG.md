# Changelog

Notable changes to the SubZeroDev GitHub Plugin. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project uses
[semantic versioning](https://semver.org/spec/v2.0.0.html).

The package version and `SCHEMA_VERSION` are deliberately separate: the first describes the
distributed code, the second governs the compatibility of exported documents. Below `1.0.0` there is
no migration path for exported documents — an incompatible document is regenerated by re-running
`export`, not upgraded.

## Unreleased

Nothing is published yet. `package.json` carries `private: true`, and publication is gated on
passing contract conformance at Milestone 8. See
[`BUILD-PLAN.md`](BUILD-PLAN.md) for the milestone sequence.

### Added

- Versioned `github.config.json` schema, `.strict()` at every level, with **no field a token value
  could occupy** — only the _name_ of an environment variable is configurable. A schema-shape test
  enforces that mechanically rather than by convention.
- Configuration loading with stable error codes, and directory resolution relative to the
  configuration file rather than the working directory.
- Token resolution: the configured environment variable first, then — opt-in only — the GitHub CLI's
  stored credential, read as a file so no `processExecution` capability is needed. The resolved
  source is always reported.
- Value-based secret scrubbing across log messages, structured fields, bound child fields, error
  messages, stacks, and `.cause` chains. `request` and `response` objects are dropped wholesale
  rather than field by field.
- A logger constructed against **stderr (`fd 2`)**, because stdout carries the result envelope and
  nothing else.
- Provider-neutral `RepositoryProvider` port, `Outcome<T, E>`, and `ProviderError` carrying the
  `code`, `subject`, `retryable`, and `status` the result envelope needs.
- Versioned domain models: repository, language statistics, releases, branches, contributors,
  statistics, summary, portfolio overrides, and the top-level documents. Identity is GitHub's
  immutable numeric ID, serialized as a string.
- `checkSchemaVersion`, distinguishing an incompatible document from an unreadable one.

### Fixed

- Ordering comparators no longer use `localeCompare`, which resolves against the environment's
  default locale and made serialized array order depend on the machine's `LANG`.
- Document timestamps now use the same bounded RFC 3339 pattern as the contract's result-envelope
  schema, so a plugin document cannot hold a timestamp the envelope would reject.

### Known limitations

Every work command — `sync`, `list`, `stats`, `export`, `validate` — still exits `3`. There is no
GitHub API access, cache, or export behaviour yet, and the contract-required `manifest` command does
not exist. See
[Where the implementation stands](https://plugins-github.subzerodev.com/docs/reference/contract-conformance).
